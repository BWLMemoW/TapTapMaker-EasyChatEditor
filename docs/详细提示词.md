# 提示词：开发 Easy-ChatBox DSL 图形化编辑器

> 本提示词由 `docs/简化需求.md` 扩写而来，用于交给 AI 或开发团队作为详细开发需求说明。
> 核心目标：做一个“简单但可用”的 Easy-ChatBox DSL 编辑器，支持语法高亮、代码补全，并能读取 `register.json` 中的注册 ID。

---

## 一、角色设定

你是一名资深的编辑器 / 前端工具链工程师，熟悉文本编辑器内核（如 CodeMirror、Monaco）、DSL 词法/语法分析、JSON 配置解析，以及桌面或 Web 工具的产品化落地。你需要在需求不明确时做出合理默认选择，并给出清晰的技术方案。

## 二、项目背景

Easy-ChatBox（简称 EC）是一个运行在游戏内部的对话 / 视觉小说演出模块。它使用一套纯文本 DSL 编写剧本，并用 `register.json` 登记所有可引用的资源 ID（角色、表情、场景、音频、装饰、变量等）。

- 剧本是**逐行解析**的纯文本，支持对话、旁白、指令、分支、选项、变量、标签跳转等。
- 剧本中引用的角色、表情、场景、音频、装饰 ID，通常**必须**先在 `register.json` 中登记。
- 当前写剧本主要靠纯文本编辑，缺少语法提示和资源 ID 校验，容易写错角色名、表情名、场景 ID 等。

因此，需要开发一个**简单的图形化 Easy-ChatBox DSL 编辑器**，让剧本编写更直观、更不容易出错。

## 三、总体目标

交付一个可运行的 Easy-ChatBox DSL 编辑器，至少包含以下三个核心能力：

1. **语法高亮**：能清晰区分 DSL 中的注释、指令、对话、旁白、选项、标签、变量插值、富文本标签、字符串、数字、布尔值等。
2. **代码补全**：在输入指令、角色、表情、场景、音频、变量、标签时给出智能补全。
3. **register.json 集成**：读取并解析 `register.json`，将注册 ID 用于补全、校验和资源面板展示。

除上述核心功能外，还应提供基础的文本编辑、文件打开/保存、错误提示等配套能力，使其成为“可以真正用来写剧本”的工具。

## 四、详细功能需求

### 4.1 编辑器基础能力

- 提供图形化界面，至少包含：
  - 主编辑区（可多标签打开多个剧本文件更佳）
  - 左侧或右侧资源面板（展示 register.json 中的角色 / 场景 / 音频 / 装饰 / 变量）
  - 顶部工具栏（新建、打开、保存、另存为、撤销、重做）
  - 底部状态栏（当前文件、行列号、register.json 加载状态、语法错误数量）
- 支持打开/保存纯文本剧本文件（建议扩展名 `.txt`，也支持 `.chat` / `.ec.txt` 等自定义扩展名）。
- 支持新建空白剧本文件。
- 支持撤销 / 重做、复制 / 剪切 / 粘贴、查找 / 替换（查找替换可作为增强项）。
- 支持显示行号和当前光标行列。
- 支持脚本文件与 `register.json` 的路径配置；默认路径为项目中的 `scripts/easy-chat/register.json`，也允许用户手动选择。

### 4.2 语法高亮

需要正确识别并高亮以下 DSL 元素：

| 类别 | 示例 | 说明 |
|------|------|------|
| 注释 | `# 这是注释` | 整行以 `#` 开头，不参与执行 |
| 旁白 | `*这是一个平凡的黄昏。` | 以 `*` 开头的叙述文本 |
| 对话 | `alice:"你好。"` | 角色 ID + 英文冒号 + 英文双引号文本 |
| 带表情对话 | `alice(happy):"今天天气真好！"` | 括号内的表情名应单独高亮 |
| 指令 | `@scene bg_classroom fade 1.0` | 所有以 `@` 开头的指令关键字 |
| 指令参数 | `bg_classroom`、`fade`、`1.0` | 按参数类型区分资源 ID、效果名、数字 |
| 选项 | `- "好啊，一起去！" >> choice_library` | 选项文本、跳转箭头、目标标签分别高亮 |
| 标签定义 | `> choice_library` | 单 `>` 标签定义 |
| 标签跳转 | `>> choice_library` | 双 `>>` 跳转 |
| 变量插值 | `{affection_alice}` | 对话/旁白中的花括号变量 |
| 富文本标签 | `[p=0.5]`、`[color=#FF0000]`、`[/color]` | 文本内部样式标签 |
| 变量赋值/条件 | `@set affection_alice +1`、`@if affection_alice >= 5` | 变量名、运算符、数字、布尔值应区分 |
| 字符串与数字 | `"第" .. day .. "章"`、`1.0` | 字符串常量、数字常量 |
| 布尔值 | `true` / `false` | 单独颜色 |

高亮要求：

- 支持一种默认深色主题，同时可扩展浅色主题。
- 高亮必须基于**词法/语法分析**，不能只靠正则匹配全文；至少要做到按行解析，避免把注释中的 `@scene` 也高亮成指令。
- 输入未完成时不能崩溃，例如 `alice:"` 未闭合、`@show ` 后面为空、`@choice` 未闭合等，应保持稳定并尽可能给出合理的临时高亮。

### 4.3 代码补全

补全触发方式：

- 输入时自动弹出（例如输入 `@`、角色名首字母、`(`、`{`、`>>` 后）。
- 支持 `Ctrl+Space` 手动触发补全。
- 支持方向键选择、`Tab`/`Enter` 确认、`Esc` 取消。

补全类型至少包括：

1. **指令补全**：输入 `@` 后补全所有 DSL 指令关键字，例如：
   `@scene`、`@show`、`@hide`、`@move`、`@highlight`、`@action`、`@scale`、`@setlayer`、
   `@bgm`、`@sfx`、`@transition`、`@shake`、`@flash`、`@tint`、`@decoration`、`@textbox`、
   `@auto`、`@set`、`@if`、`@else if`、`@else`、`@endif`、`@choice`、`@timeout`、
   `@call`、`@return`、`@savepoint`、`@wait`、`@end`。
2. **角色 ID 补全**：
   - 在对话行开头输入角色名前缀时，补全 `register.json` 中 `characters` 的角色 ID。
   - 在 `@show`、`@hide`、`@move`、`@highlight`、`@action`、`@scale`、`@setlayer` 后补全角色 ID。
3. **表情补全**：
   - 在 `角色ID(` 后补全该角色 `sprites` 中已登记的表情名。
   - 在 `@show 角色ID` 后补全表情名。
4. **场景 ID 补全**：在 `@scene` 后补全 `scenes` 中的场景 ID。
5. **音频 ID 补全**：
   - 在 `@bgm` 后补全 `audios` 中 `type` 为 `"bgm"` 的音频 ID。
   - 在 `@sfx` 后补全 `audios` 中 `type` 为 `"sfx"` 的音频 ID。
6. **装饰 ID 补全**：在 `@decoration` 后补全 `decorations` 中的装饰 ID。
7. **变量补全**：
   - 在 `@set`、`@if`、`{` 后补全 `variables`、`flags` 以及当前剧本中已通过 `@set` 创建过的变量名。
8. **标签补全**：在 `>>` 后补全当前剧本中已定义的标签名（单 `>` 定义过的）。
9. **子剧本补全**：在 `@call` 后补全外部传入的 `sources` 文件名（如有），或项目内约定目录下的剧本文件（可作为增强项）。
10. **片段补全（Snippets）**：
    - `@choice` 选项块模板
    - `@if / @else / @endif` 模板
    - 常见演出序列模板，例如 `@scene + @show + @wait + 对话`
    - `@bgm / @sfx` 常用写法

补全建议附带信息：

- 角色补全时显示 `display_name`、表情数量、默认位置。
- 场景补全时显示 `type`（background / cg）。
- 音频补全时显示 `type`、`volume`、`loop`。
- 指令补全时显示简要说明或使用格式，例如 `@scene 场景ID [转场] [时长]`。

### 4.4 register.json 集成

- 支持从默认路径或用户指定路径加载 `register.json`。
- 解析失败时给出明确错误提示（例如 JSON 格式错误、字段缺失），但不影响编辑器打开剧本。
- 加载成功后，将以下注册数据建立索引，供补全和校验使用：
  - `characters`：ID、display_name、sprites、default_expression、default_position、image_name_tag
  - `scenes`：ID、type、transition、duration
  - `audios`：ID、type、volume、loop
  - `decorations`：ID、image、description
  - `variables`：变量名与初始值
  - `flags`：布尔开关名
  - `ui_elements`：UI 配置（主要展示，不参与补全也可）
- 支持**重新加载**：用户点击刷新按钮，或当 `register.json` 文件发生变化时自动重新加载（文件监听为增强项）。
- 当 register.json 未找到时，编辑器应降级运行：
  - 语法高亮仍可用；
  - 指令补全仍可用；
  - 角色/场景/音频等依赖注册数据的补全不展示；
  - 状态栏提示“未找到 register.json”。

### 4.5 校验与诊断（强烈建议包含）

虽然不是最初三条需求之一，但读取 register.json 后自然应该提供基础校验，让编辑器真正可用：

- 语法错误：
  - `@choice` 块未闭合（缺少 `@end`）
  - `@if` 块未闭合（缺少 `@endif`）
  - 对话行缺少角色 ID 或引号不完整
  - 选项缺少 `>> 标签`
- ID 校验：
  - 对话角色未在 register 中注册
  - `@show / @hide / @move` 等引用了未注册角色
  - 角色表情未在该角色 `sprites` 中登记
  - `@scene` 引用了未注册场景
  - `@bgm / @sfx` 引用了未注册或类型不匹配的音频
  - `@decoration` 引用了未注册装饰
- 标签校验：
  - `>> xxx` 跳转目标在当前剧本中不存在
  - 同一个标签重复定义
- 诊断展示：
  - 在对应行行号处显示错误/警告标记
  - 底部或侧边错误面板列出问题、行号、说明
  - 支持点击错误跳转到对应行

校验结果可分为 `error`（阻断剧本运行）和 `warning`（提示但不阻断），与 EC 现有行为保持一致。

### 4.6 资源面板

- 以树形或列表展示 register.json 内容：
  - 角色：ID、显示名、表情列表、默认位置
  - 场景：ID、类型
  - 音频：ID、类型、音量
  - 装饰：ID、描述
  - 变量 / 开关：名称与初始值
- 点击资源项时，可将对应 ID 插入编辑器光标处（或复制到剪贴板）。
- 资源面板支持搜索过滤。

### 4.7 界面与交互

- 界面语言使用中文（至少中文文案），代码/ID 保持英文原样。
- 默认布局：
  - 左侧：资源面板（可折叠）
  - 中间：编辑区
  - 底部：诊断/输出面板（可折叠）
- 常用快捷键：
  - `Ctrl+N` 新建
  - `Ctrl+O` 打开
  - `Ctrl+S` 保存
  - `Ctrl+Z` / `Ctrl+Y` 撤销/重做
  - `Ctrl+F` 查找
  - `Ctrl+Space` 手动补全
- 在文件未保存时，关闭或切换文件应有“是否保存”提示。

## 五、技术选型建议

需求不强制指定技术栈，但建议按下述方向选型，并说明理由：

### 方案 A：Web 编辑器（推荐做原型 / 轻量工具）

- 技术栈：TypeScript + Vite + CodeMirror 6
- 编辑器内核：CodeMirror 6（体积小、适合自定义 DSL 高亮与补全）
- 文件读写：浏览器 File System Access API，或 Electron/Tauri 提供原生文件对话框
- 优点：开发快、跨平台、易嵌入 Web
- 缺点：纯浏览器场景下保存本地文件体验受限，建议打包为桌面应用

### 方案 B：桌面应用

- 技术栈：Electron 或 Tauri + Monaco Editor / CodeMirror 6
- 优点：原生文件读写、项目目录监听、资源路径解析更自然
- 缺点：打包体积较大 / 需要 Rust 环境（Tauri）

### 方案 C：VS Code 扩展

- 如果目标用户已使用 VS Code，可做成扩展：
  - 用 TextMate grammar 实现语法高亮
  - 用 LSP 或 extension API 实现补全/诊断
  - 读取 workspace 中的 register.json
- 优点：开发成本低，复用编辑器能力
- 缺点：不是独立图形化工具

无论选择哪种方案，都建议将“词法分析、语法解析、register 数据源、补全提供器、诊断器”拆分为独立模块，便于测试和复用。

## 六、非功能需求

- **易用性**：界面简洁，默认配置即可使用，不需要用户了解内部实现。
- **稳定性**：输入任意文本（包括不完整、错误语法）都不应崩溃。
- **性能**：打开 1 万行左右的剧本仍能流畅滚动、高亮、补全。
- **可维护性**：代码结构清晰，核心解析逻辑有单元测试。
- **可移植性**：如果做桌面工具，至少支持 Windows；macOS/Linux 作为加分项。
- **可测试性**：词法高亮、补全建议、ID 校验应有自动化测试用例。

## 七、验收标准

1. 启动编辑器后，可以新建/打开/保存 `.txt` 剧本文件。
2. 输入 DSL 时，注释、旁白、对话、指令、选项、标签、变量插值等有明显不同的颜色高亮。
3. 输入 `@` 能弹出指令补全；输入角色名前缀能补全 register.json 中的角色 ID。
4. 在 `@scene` 后能补全场景 ID；在 `@bgm` / `@sfx` 后能按类型补全音频 ID；在 `角色ID(` 后能补全该角色表情。
5. 加载 register.json 后，资源面板能正确展示角色、场景、音频、装饰、变量。
6. 对未注册 ID、未知表情、未闭合 `@choice`、跳转目标不存在等情况，能在对应行给出错误或警告提示。
7. register.json 缺失或损坏时，编辑器仍可打开剧本并进行基础语法高亮和指令补全，同时给出明确提示。
8. 附 README，说明如何安装、运行、配置 register.json 路径，以及如何扩展指令/补全规则。

## 八、交付物

- 可运行的编辑器源码（含必要依赖与启动脚本）
- 示例 `register.json`
- 示例 Easy-ChatBox 剧本（覆盖对话、旁白、选项、分支、变量、标签、子剧本等特性）
- 自动化测试（至少覆盖词法高亮分类、补全候选、ID 校验）
- README：安装、运行、使用说明、架构说明、扩展指南

## 九、实现优先级建议

1. **P0（必须）**：基础编辑界面 + 文件打开/保存 + 语法高亮 + register.json 读取 + 角色/场景/音频/装饰/变量补全 + 基础诊断。
2. **P1（强烈建议）**：资源面板、错误面板、标签跳转校验、表情补全、Snippets、文件监听重载。
3. **P2（增强）**：多标签、查找替换、子剧本文件补全、深浅主题切换、导出/导入配置、项目级目录管理。

## 十、Easy-ChatBox DSL 速查（供实现参考）

```text
# 注释
* 旁白文本
alice:"你好，世界。"
alice(happy):"今天天气真好！"

@scene bg_classroom fade 1.0
@show alice default center slide_left
@wait 0.6

@choice
- "你好呀" >> say_hi
- "再见" >> say_bye
@timeout 8 >> say_timeout
@end

> say_hi
@set affection_alice +1
alice:"很高兴认识你！"
>> the_end

> the_end
@end
```

- 指令以 `@` 开头，行尾通常无分号。
- `@choice` 块以 `@end` 闭合；`@if` 块以 `@endif` 闭合。
- 单 `>` 定义标签，双 `>>` 跳转标签。
- 变量插值用 `{变量名}`；`@set` 可新建变量。
- 所有资源 ID 优先从 `register.json` 获取。
